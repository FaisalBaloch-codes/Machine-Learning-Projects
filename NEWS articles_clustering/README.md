# News Article Clustering (Feature Engineering + K-Means + Hierarchical)

## Project Objective
This project has two stages:

1. **Feature Engineering** — build numeric structural features directly from raw
   news headlines (title length, punctuation, sentiment, etc.)
2. **Clustering** — use those engineered features to discover natural groupings
   of similar articles, with **no knowledge of the true `Category` label**
   (unsupervised learning). K-Means and Agglomerative Hierarchical Clustering
   are both implemented and compared.

## Input Dataset
`data/News_Classification_Labeling.xlsx` — 5000 news headlines, 3 raw columns:
`URL`, `Title`, `Category` (6 categories: Business, Markets, Politics,
Technology, Health, Energy).

## Features Used (for clustering)
7 numeric features engineered from `Title` text (`src/feature_engineering.py`):

| Feature | What it measures |
|---|---|
| `title_len` | Character length of the title |
| `num_digits_count` | Count of digit characters |
| `question_mark_count` | Count of `?` characters |
| `punctuation_count` | Count of punctuation characters |
| `sentiment_score` | VADER compound sentiment score (-1 to +1) |
| `poi_count` | Count of multi-word capitalized phrases (proxy for named entities) |
| `has_location` | 1 if a country/city keyword appears in the title |

## Features Excluded (and why)
- **`URL`** — identifier, not a numeric feature.
- **`Title`** — raw text; already converted into the 7 numeric features above.
- **`Category`** — the known label. **Never used to form clusters.** Clustering
  is unsupervised — feeding in the answer would defeat the purpose. `Category`
  is preserved separately and only reattached *after* clustering, purely for
  interpretation (see `results/cluster_category_analysis.csv`).

## What Clustering Means
Clustering groups similar data points together *without* being told the correct
groups in advance. The algorithm only sees the 7 numeric features per title; it
has no idea what `Category` each title actually belongs to.

### K-Means
Partitions points into K clusters by repeatedly assigning each point to its
nearest cluster center and recomputing centers, until stable. Requires choosing
K in advance.

**K selection — Silhouette Score:** For each point, compares how close it is to
its own cluster vs. the nearest other cluster (range -1 to +1, higher is
better). K = 2 through 10 were tested; the K with the highest average
Silhouette Score was selected. See `results/kmeans_scores.csv` and
`results/silhouette_scores.png`.

### Hierarchical Clustering (Agglomerative)
Bottom-up: every point starts as its own cluster; the two closest clusters
merge repeatedly until everything is one cluster, forming a tree (dendrogram).
**Ward linkage** is used (merges that minimize the increase in within-cluster
variance — produces compact, evenly-sized clusters).

**Distance threshold:** cutting the dendrogram at a given distance gives a
specific number of clusters. Rather than an arbitrary number, a **largest-gap
heuristic** looks at the last 15 merge distances and finds the biggest jump —
the threshold is set at the midpoint of that gap. See
`results/hierarchical_threshold.txt` and `results/hierarchical_dendrogram.png`.

## How to Interpret the Results
- **Best K (K-Means):** 2, with Silhouette Score ≈ 0.27 (highest among K=2–10).
  A secondary local peak appears around K=5 — see the notebook for discussion
  of this trade-off.
- **Hierarchical:** the largest-gap threshold produced 5 clusters, of quite
  different sizes.
- Both methods separate titles mainly by **writing style** (length,
  punctuation, sentiment) rather than topic, since that's what the 7 engineered
  features actually capture. **Neither result should be read as recovering the
  true news categories** — that was never the goal, and Category was withheld
  from the clustering process entirely.

## Limitations
- The clustering input is only 7 structural/stylistic features derived from
  the title text — not the article's actual topical content (no TF-IDF /
  word-based features were included in clustering, to keep dimensionality
  and distance calculations meaningful for K-Means/Ward linkage).
- `poi_count` and `has_location` are simple regex/keyword-based approximations,
  not a full named-entity recognition system.
- Clustering results depend on the chosen features; different feature choices
  would likely produce different clusters.
- As with the earlier classification project, note that ~4.5% of titles in
  this dataset are duplicated with different Category labels — this doesn't
  affect clustering (which ignores Category), but is worth knowing when
  interpreting `cluster_category_analysis.csv`.
